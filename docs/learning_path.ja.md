# ROS 2でPhysical AIを実装するための教材

[操作の入口へ戻る](../README.md)

テレオペでFollowerを動かせても、通信が途絶えたときにどこで止まるか、どの画像と指令を学習へ使うかは、動く様子だけでは分かりません。設定、メッセージ、実機の数値を対応付けて読むと、同じ構成を自分で設計し直す判断材料になります。

この教材は、SO-101の現在の実装を具体例に、観測・制御・記録・学習・モデル実行を説明します。ROS 2や機械学習の専門用語は初出で意味を添え、一般的な考え方と、この機体だけの設定を分けています。別の機体で必要な周期や保護値は、その機器の仕様と測定から決めます。

## 手元の疑問から読む

| 疑問 | 読む教材 |
|---|---|
| 起動したのに動かない、モードやトルクが分からない | 3と4 |
| 解像度やFPSが設定どおりにならない、容量が増える | 5 |
| timestampはあるが、画像とactionの対応が分からない | 5と6 |
| 収集した後の変換や学習に何が必要か知りたい | 6と7 |
| 学習は終わったが実機でうまくいかない | 7と8 |
| 他のモーターやロボットで作りたい | 1〜4で分担を確認し、9の仕様表を作る |

## 読みながら残す記録

例えば「30 FPS設定でも配信は約15 FPSだった」と観察したら、使った設定、画像サイズ、取得・配信・保存のどの値を測ったかを残します。原因を確認できていなければ、推測と測定結果を分けて書きます。次に同じ現象が起きたとき、別の機体でも比較できる記録になります。

自分で実装するときは、機体の仕様表、観測から指令までの構成図、設定と単位の対応、停止の条件、Episodeの採用条件、学習・検証の分割、実機評価の結果を残します。書き出せない項目があれば、実装前に仕様や確認が必要な部分を特定できます。

## 現在の実装と教材の範囲

実機の通信・校正、ROSの制御・記録、Dataset変換、独自ACTと小型flow、RTC・Training-time RTC・VLASH・A2C2を扱います。[モデル選択](methods/models.ja.md)ではSmolVLAなど8モデルの学習・実行も扱います。登録モデルは単一タスク向けです。MoveItのPlanner・IK・実機の衝突回避、カメラの自動校正は別の実装が必要です。

小規模学習やmockの試験結果を、物体操作の成功率として読み替えません。実装済みの範囲と未確認の条件は[実装状況](implementation_status.ja.md)、実際の試験条件は[検証記録](validation.ja.md#methods)で確認できます。
