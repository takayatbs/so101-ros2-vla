# 記録データを同期再生・EE軌跡・品質指標で確認する

[収集手順へ戻る](collection_script.ja.md) ／ [手順書一覧](index.ja.md)

`visualize_recording.sh` は、収集したデータをブラウザで確認する画面を生成します。複数カメラの共通再生、関節・指令との照合、EEの3D軌跡、全Episodeの比較、確認結果の書き出しを1画面で扱います。元の記録・採用可否・学習データは変更しません。

## 1. 確認画面を生成する

Runtime・学習・Probeを終了してから、プロジェクトの端末で実行します。

```bash
# 入力を省略すると、元記録が残っている最新の終了済みSessionを選ぶ
./scripts/visualize_recording.sh

# Sessionを指定する
./scripts/visualize_recording.sh data/collections/SESSION_ID

# data/bags直下のEpisodeをまとめて確認する
./scripts/visualize_recording.sh data/bags

# 単体のEpisodeやMCAPを指定する
./scripts/visualize_recording.sh data/bags/EPISODE_ID
./scripts/visualize_recording.sh data/bags/EPISODE_ID/raw/raw_0.mcap
```

既定は失敗・やり直しを含む全試行と、設定された全カメラが対象です。採用したEpisodeだけなら `--accepted-only`、カメラを選ぶ場合は `--cameras top arm` を追加します。Sessionは記録されたSystem設定を使います。単体Episodeやbags全体では `config/runtime/system.real30hz.640x480.h264.yaml` が既定です。別の設定で収集した場合は `--config` で収集時の設定を指定してください。

```bash
./scripts/visualize_recording.sh data/collections/SESSION_ID \
  --accepted-only --cameras top arm \
  --output data/reviews/collection-review-v1
```

`--output` を省略すると `data/reviews/` の下に毎回新しい出力を作ります。指定した出力先が存在する場合は上書きしません。読み込めないEpisodeがある場合は、生成できた記録と未生成の一覧・理由を表示します。全件が読めない場合は生成を中止します。

### 並列数と進捗

Episodeごとに別プロセスで動画・同期・EE解析・画面生成を実行します。既定の `--workers 0` はCPU割当と空きメモリー、Dataset設定のEpisodeメモリー上限を基に最大4並列を選びます。1本だけの入力では1プロセスです。

```bash
# 並列数を明示する
./scripts/visualize_recording.sh data/collections/SESSION_ID --workers 4

# 従来と同じ順次処理
./scripts/visualize_recording.sh data/collections/SESSION_ID --workers 1
```

Raw画像を取り込む場合はカメラごとにNVENCを使用するため、自動設定は1プロセスに抑えます。NVENCの同時セッション数とメモリーに余裕がある環境では `--workers` で増やせます。H.264記録は再エンコードせず、復号による検証とMP4への格納を並列で行います。既存レビュー・Datasetの取り込みにも並列設定を使えます。

端末には開始・完了したEpisode、完了本数、Episodeごとの処理秒数を表示します。出力の `generation.json` に実際の並列数・合計時間・未生成本数も保存します。完了順にかかわらず画面のEpisode順、時刻、比較指標は入力順を維持します。Ctrl+Cでは実行中Episodeの処理終了を待ち、一時出力を片付けます。元データは変更しません。

処理の途中に保存したコード変更は、実行済みプロセスへ反映されません。並列化の変更は次回の起動から有効です。可視化全体はRuntime・学習との排他を維持します。

## 2. 既存の動画を再利用する

すでに生成したレビューや変換済みDataset v2も入力にできます。元MCAPから動画を作り直す時間を省けます。

```bash
# 旧版を含む既存レビューを新しい画面へ変換する
./scripts/visualize_recording.sh data/reviews/EXISTING_REVIEW \
  --output data/reviews/new-review

# 学習へ渡すDatasetそのものを確認する
./scripts/visualize_recording.sh data/datasets/DATASET_NAME \
  --output data/reviews/dataset-review
```

既存のレビュー・Datasetでは元の対応付けを維持します。カメラ構成を変更して同期をやり直す場合は、元のSessionやEpisodeを入力にしてください。

同じファイルシステムでは動画をハードリンクで再利用し、使えない環境ではコピーします。生成処理では動画の再エンコードや内容の変更はしません。操作用PCへは新しい出力フォルダー全体をコピーすれば持ち出せます。

## 3. ブラウザで開く

終了時に表示された `index.html` をH.264対応ブラウザで開きます。外部CDNやサーバーへの接続は不要で、ファイルを直接開けます。

操作用PCでは出力フォルダー全体をコピーします。`OUTPUT_DIRECTORY` を終了時に表示されたフォルダー名へ置き換えます。

```bash
scp -r \
  'robot-user@robot-host:/path/to/so101-ros2-vla/data/reviews/OUTPUT_DIRECTORY' \
  ~/Downloads/
open ~/Downloads/OUTPUT_DIRECTORY/index.html
```

HTMLだけでは動画を表示できません。出力フォルダーを丸ごと取得してください。

## 4. 全カメラを同時に再生する

左の一覧からEpisodeを選び、画面下の共通操作を使います。動画ごとの再生操作はありません。

| 操作 | 動作 |
|---|---|
| 再生・停止 / Space | 全カメラを同時に再生・停止する |
| 共通スライダー | 全映像、関節・指令グラフ、EE位置、品質タイムラインを同じ記録時刻へ移す |
| ◀│ / │▶ または ← / → | 対応表の1行ずつ前後へ移動する |
| 再生速度 | 全カメラを0.25倍・0.5倍・1倍・2倍へ切り替える |
| 開始点・終了点、ループ | 確認したい区間だけを繰り返し再生する |
| 拡大 | カメラ1台の表示を大きくする。共通の再生操作は維持する |

再生中は動画の元時刻を揃えて追従させ、読み込み待ちが出た場合は全カメラを待機させます。停止してスライダーを動かした場合は、対応表で実際に選ばれた画像へシークします。そのため停止中のカメラ表示の時刻は、基準時刻より少し前になることがあります。

カメラ欄の「古さ」は選択された画像の基準時刻からの差、「同期差」はブラウザ再生中の共通時刻との差です。表示欄にマウスを重ねると、ブラウザ側の表示落ちも確認できます。これらはRecorder受信遅延とは別です。

## 5. Episodeの映像・状態・EEを確認する

映像と3Dを同時に見ながら、最初は `gripper` の開閉やアームの方向転換を追います。

| 画面 | 確認するもの |
|---|---|
| 同期映像 | 作業が成功したか、配置戻しや人の手が記録に入っていないか、物体が画角から外れないか、遮蔽やぼけがないか |
| EE trajectory | 実測関節から推定したEEの軌跡・現在位置・アームの概形。目標関節から推定した軌跡も重ねる |
| Signals | 関節位置と送信済み目標、EEのXYZ位置、EE速度、同期の時刻差、Recorder受信遅延を切り替える |
| Quality | 同期条件内・警告・除外の行数、原記録のカバー率と対応範囲外の先頭・末尾、実FPS、最大取得間隔、同じ画像の再使用、受信遅延P95、30行チャンクを全長で取れる割合 |
| 確認候補 | 同期条件外・EE速度が大きい区間へ移動する。候補は作業失敗の自動判定ではない |

3Dはドラッグで回転、Shift＋ドラッグで移動、ホイールで拡大できます。「上」「正面」「斜め」「全体」で視点を戻せます。座標の単位はmです。実測からの推定が緑、送信済み目標からの推定が橙です。

グラフや品質タイムラインをクリックしても共通時刻を移動できます。J / Kで前後の確認候補へ、Bで現在時刻にマーカーを追加できます。物体を挟んでいる間の目標と実測位置の差は、遅延だけでは説明できません。

## 6. 全Episodeの軌跡と一貫性を確認する

「全体比較・EE軌跡」へ切り替えます。

- 同じタスク・ロボット設定・校正情報・EEモデルの記録を比較グループとして表示します。
- 各実演の軌跡、始点・終点、共通の進捗位置、基準群の平均軌跡を重ねます。既定では収集時の失敗・対象外を外し、チェックで表示対象に加えられます。
- 収集順、時間、同期品質、軌跡のずれ、始点・終点のずれで一覧を並べ替えられます。一覧のIDを押すと、その実演の映像へ戻ります。
- 「開始位置を揃えて形状を比較」で、初期位置の違いを取り除いた相対的な形状を見られます。初期位置のばらつきも確認する場合はチェックを外します。

軌跡ずれは、各実演を0〜100%の進捗に揃え、同じグループの他の採用・成功試行の平均位置に対する距離のRMSで表します。始点・終点のずれも他の基準試行を使います。基準になる別試行がない場合は「—」です。同期条件外の区間をまたいで補間しません。

速度や待ち時間、初期配置、正当な動作の違いでもずれは大きくなります。数値の大きい試行を映像で確認するための手掛かりとして使い、機械的に除外しないでください。同一Session内の一致だけでは、別配置・別環境への汎化性能は評価できません。

## 7. EEモデルとTCPを指定する

**現在の既定URDFは、統合テスト用の近似モデルです。既定のEE位置は実機で計測した把持点ではありません。** 画面にも近似モデル・未校正と表示します。既定は `base_link` から `gripper_link` 原点まで、TCPオフセットは0です。

実機に合ったURDFと、関節のゼロ位置・方向・TCPの対応を確認できている場合は指定できます。

```bash
./scripts/visualize_recording.sh data/collections/SESSION_ID \
  --urdf /workspace/path/to/robot.urdf \
  --base-frame base_link \
  --ee-frame tool0 \
  --tcp-xyz 0 0 0.03
```

`--tcp-xyz` はEEフレーム内のオフセットで単位はmです。URDF側の可動関節名は記録の関節名に合わせます。固定・回転・連続回転・直動・mimic関節を扱います。必要な関節が記録にない場合は0と推測せず、EEを計算できない理由を表示します。

モデルと状態・指令が一致しても、実機との幾何校正が自動で完了するわけではありません。近似モデルの軌跡ずれや速度を、実機の絶対位置精度や安全な動作領域の合否判定には使わないでください。

## 8. 確認結果を保存・持ち出す

Review欄で「未確認」「確認済み」「要確認」「対象外候補」を選び、所見、時刻マーカー、確認範囲を残せます。変更はブラウザ内に保存します。ブラウザやPCを変える場合は書き出してください。

- 「確認結果を書き出す」: 判定・所見・時刻マーカー・確認範囲をJSONに保存する。
- 「結果を読み込む」: 同じEpisode IDの確認結果を読み込む。
- 「一覧CSV」: 全Episodeの品質指標・EE比較値・確認判定・所見を一覧として保存する。

確認範囲の `start_s` / `end_s` とマーカーの `t` は、JSON内の `time_origin_timestamp_ns` を0秒とした秒数です。原記録の開始時刻 `source_start_time_ns` と異なる場合があります。ナノ秒時刻は精度を保つため文字列で保存します。

この判定と確認範囲はレビュー用です。元の `collection.json` の採用変更、動画のトリミング、学習Datasetの更新は行いません。学習へ反映する前に、採用対象・範囲を別途適用します。

## 時刻差の意味と計測の範囲

- 同期の時刻差は「基準時刻 − 取得元時刻」の古さです。元の対応表の `errors` は逆符号の「取得元時刻 − 基準時刻」で保持しています。
- 同期条件内の割合は、共通の対応表に含まれる行だけが母数です。原記録のカバー率と先頭・末尾の対応範囲外時間も併せて確認します。元の開始・終了時刻がない場合はカバー率を表示できません。
- 現在の同期条件の20ms警告・50ms除外は対応付けの条件で、受信遅延の合否条件ではありません。
- 受信遅延は「Recorder受信時刻 − 取得元時刻」です。カメラではホスト取得から圧縮・配信を経てRecorderに届くまで、実測状態では読み取り完了から受信までです。
- 取得間隔が約68ms空いたことと、約68ms遅れて届くことは別です。
- センサー露光時刻、操作用PCでの表示完了、サーボの物理応答、ディスク永続化完了は計測していません。
- デコードに必要な記録開始前のキーフレーム区間は保持しますが、受信遅延の集計はEpisode内だけを対象にします。
- 時刻索引のない古い記録やDatasetからの入力では、受信遅延が取得できない場合があります。「—」やデータなし表示を0msと解釈しないでください。

出力先の `workspace.json` と `review_manifest.json` に一覧・品質・比較値を保存します。各Episodeの `review.html`、`review_data.js`、動画も出力内に収まるので、フォルダーごと持ち出せます。確認用出力は学習Datasetとして登録しません。

カメラの配信待ちを測り直す場合は[カメラ遅延の変更と測定方法](camera_latency.ja.md)を参照してください。
