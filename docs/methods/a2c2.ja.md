# A2C2：最新観測で動作を補正する

[手法の入口へ戻る](index.ja.md) ／ [RTCの学習](rtc.ja.md) ／ [VLASHの学習](vlash.ja.md)

A2C2は、ベースモデルが作った動作列へ、現在の観測から計算した補正を加える追加機能です。ベースモデルを学習した後に、軽い補正器を別途学習します。

[モデル選択](models.ja.md)で登録したLeRobotモデルも、同じ `prepare-a2c2`・`train-a2c2` で扱えます。モデルごとに対応する `standard`・RTC・Training-time RTC・VLASHへ追加し、`deploy_policy.sh --correction` で起動します。

## 1. 何を学習するのか

物体へ向かう動作列を作った後に、物体やアームが少しずれた場面を考えます。古い画像から作った動作をそのまま使う代わりに、最新画像・関節状態と、その動作がチャンクの何番目かを使って補正します。

```text
ベースモデルの予測action ＋ 補正器の出力 ＝ 実行するaction
補正器の教師データ ＝ 記録の正解action − ベースモデルの予測action
```

元データを収集し直す工程ではありません。学習済みモデルを収集データへ適用して、補正学習用キャッシュを作ります。最新観測の特徴・ベースaction・チャンク位置・遅延・元Episodeを対応付けます。

## 2. 先にベースモデルを用意する

まず[RTC](rtc.ja.md)の手順で `rtc-v1` を学習します。VLASHと組み合わせる場合は[VLASH](vlash.ja.md)で `vlash-v1` を学習します。

以下はRTC＋A2C2の例です。

## 3. 補正学習用キャッシュを作る

Runtimeを停止して実行します。

```bash
./scripts/methods.sh prepare-a2c2 \
  --model /workspace/data/models/rtc-v1 \
  --dataset /workspace/data/datasets/pick-place-lerobot-v1 \
  --output /workspace/data/datasets/rtc-a2c2-cache-v1
```

`samples.npz` と `cache.json` が生成されます。ベースモデルを固定して予測し、元Episodeの学習・検証の分割を引き継ぎます。既定は4フレームおきに予測を開始して複数のチャンク位置を作ります。メモリー量が大きい場合は `--stride 8` などで開始点を間引けます。

RTC／Training-time RTCでは既知prefix、VLASHでは将来状態の時間ずらしも模擬します。記録されたデモを使う補正学習であり、実機で発生するすべての状態ずれを再現したデータではありません。

## 4. 補正器を学習する

```bash
./scripts/methods.sh train-a2c2 \
  --cache /workspace/data/datasets/rtc-a2c2-cache-v1 \
  --output /workspace/data/corrections/rtc-a2c2-v1 \
  --steps 5000
```

`config.json`、`model.safetensors`、`metrics.json` が保存されます。`validation_mse` は学習に使わない元Episodeからの値です。検証用Episodeがない場合はnullです。

キャッシュと補正器は、ベースモデルの重み・正規化・設定の指紋にひも付いています。ベースモデルを再学習した場合、古い補正器は流用できません。キャッシュから作り直します。

## 5. 補正を含めてオフライン評価する

```bash
./scripts/methods.sh evaluate \
  --model /workspace/data/models/rtc-v1 \
  --dataset /workspace/data/datasets/pick-place-lerobot-v1 \
  --correction /workspace/data/corrections/rtc-a2c2-v1 \
  --output /workspace/data/logs/evaluation/rtc-a2c2-v1.json
```

補正なしの評価と同じ遅延・検証Episodeで比較します。誤差が小さくなることと、実機タスクの成功率が上がることは別々に確認します。

## 6. RTC＋A2C2を起動する

```bash
./scripts/deploy_policy.sh rtc-v1 mock \
  --correction /workspace/data/corrections/rtc-a2c2-v1
```

準備完了を確認してから `./scripts/mode.sh AUTONOMOUS` を選びます。推論中も以前の動作列を実行し、補正器は各制御ステップの最新観測を使います。補正後も既存のSafetyとControllerを通ります。

実機受入と共通の起動前確認を済ませた実機試行では、mockをrealへ変えます。終了は記録停止 → IDLE → RuntimeのCtrl+Cです。

## 7. VLASH＋A2C2の場合

上のコマンドを次の対応で変更します。

| RTCの例 | VLASHへ変更する値 |
|---|---|
| `data/models/rtc-v1` | `data/models/vlash-v1` |
| `rtc-a2c2-cache-v1` | `vlash-a2c2-cache-v1` |
| `rtc-a2c2-v1` | `vlash-a2c2-v1` |
| `config/runtime/system.real30hz.640x480.rtc.a2c2.yaml` | `config/runtime/system.real30hz.640x480.vlash.a2c2.yaml` |

RTC用の補正器をVLASHへそのまま付けることはできません。モデル指紋と手法の一致を起動時に確認します。

原典：[Leave No Observation Behind](https://arxiv.org/abs/2509.23224)。この実装の補正器は小型MLPで、最新画像・関節の特徴は固定したベースモデルのencoderから得ます。
